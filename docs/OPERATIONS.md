# Operations

Scope: a project generated by `aurifex new` on stack `grammy` or `aiogram`, plus the
repository scripts used to operate it. Generated runtime sources live in
[`src/core/projects/templates/`](../src/core/projects/templates/).

## Secrets

Every file-backed secret supports `<NAME>_FILE`. File content wins over the plain
variable. The loader is rendered by
[`runtime-secrets.ts`](../src/core/projects/templates/runtime-secrets.ts).

- Supported names: `BOT_TOKEN`, `WEBHOOK_SECRET`, `DATABASE_URL`, `REDIS_URL`,
  `LLM_API_KEY`.
- Exactly one trailing `\n` or `\r\n` is removed. Other whitespace is preserved.
- An empty file is an error, not an empty value.
- A missing or unreadable file is an error.
- POSIX: symlinks are refused, the target must be a regular file, and a group- or
  world-readable mode prints a warning unless `NODE_ENV=test` (TypeScript) or
  `PYTEST_CURRENT_TEST` is set (Python).
- Files larger than 64 KiB are rejected.
- Values are never logged. CLI output passes through `redactSecrets`
  ([`security/secrets.ts`](../src/core/security/secrets.ts)).

Docker Compose mounts external secret files and sets `*_FILE`. Secret files live
under `secrets/`, which is gitignored.

Required at startup:

| Condition                                                                       | Required variable             |
| ------------------------------------------------------------------------------- | ----------------------------- |
| always                                                                          | `BOT_TOKEN`, `WEBHOOK_SECRET` |
| `runtime.queue === "postgres"`                                                  | `DATABASE_URL`                |
| `security.idempotency`, `security.rateLimit`, or `features` contains `miniapps` | `REDIS_URL`                   |

One failure lists every missing name, for example
`missing required configuration: DATABASE_URL, REDIS_URL`. Compose additionally
requires `POSTGRES_PASSWORD` and `REDIS_PASSWORD` to be nonempty.

`ADMIN_IDS` is a comma-separated allowlist. Empty means every admin command is
denied. It is not a secret, but it is an authorization boundary.

## Startup and migrations

Generated Compose services: `bot`, `caddy`, and, when required, `postgres`,
`redis`, `migrate`, and `worker`. `bot` and `worker` wait for `postgres` and
`redis` health, then for `migrate` to complete successfully.

- grammY: `migrate` runs `node dist/migrate.js`. The runner applies the checked-in
  SQL from `drizzle/0001_runtime_schema.sql` inside one transaction under advisory
  lock `9100000001`, then records the name in `schema_migrations`. A repeated run is
  a no-op.
- aiogram: `migrate` runs `uv run alembic upgrade head`.

Run the one-shot service manually when operating outside Compose:

```text
docker compose run --rm migrate
```

Migrations create `jobs` plus the payment, refund, subscription, broadcast, and
user tables required by the enabled features. Back up before changing schema.

## Worker

The worker exists only when `runtime.queue === "postgres"`. The webhook process
never executes jobs.

- Entrypoint: `dist/worker.js` (grammY) or `python -m app.worker` (aiogram).
- Five concurrent claim loops. Each claim locks one row with
  `FOR UPDATE SKIP LOCKED`; `QUEUE_BATCH` is accepted by config but the current
  loop claims one job at a time.
- Idle sleep: `QUEUE_POLL_MS` (default 500 ms).
- Retry: attempts increment on claim. After failure the job returns to `pending`
  with `5 * 2^attempts` seconds of delay, capped at 300 seconds. At
  `attempts >= max_attempts` it becomes `dead`.
- `last_error` is clipped to 2 KiB.
- On start, running jobs older than `QUEUE_VISIBILITY_TIMEOUT_SECONDS` return to
  `pending`.
- SIGINT/SIGTERM abort the loop, wait up to 30 seconds for in-flight jobs, close
  Redis and Postgres, and exit. Compose sets `stop_grace_period: 35s`.
- A missing handler fails the job; it is not silently dropped.

Handlers are at-least-once. Use the job idempotency key for side effects.

## Readiness, metrics, tracing

| Route          | Behavior                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /healthz` | 200 `{"ok":true}`; no dependency check                                                                                                   |
| `GET /readyz`  | `SELECT 1` for Postgres and `PING` for Redis when configured; 200 when each check is `ok` or `skip`, otherwise 503 with per-check status |
| `GET /metrics` | Prometheus text `text/plain; version=0.0.4` when `METRICS_ENABLED` is true                                                               |

Metric names: `bot_updates_total`, `telegram_api_duration_seconds`,
`job_duration_seconds`, `job_failures_total`, `queue_depth`,
`miniapp_sessions_active`. No user id or secret is a label.

OTLP traces start only when `OTEL_EXPORTER_OTLP_ENDPOINT` is nonempty. Service name
is `OTEL_SERVICE_NAME` or the bot name. Sentry starts only when `SENTRY_DSN` is
nonempty, with `tracesSampleRate: 0.1`. The telemetry module exposes `traceId()` /
`trace_id()` so a log line can carry the active trace id; the generated logger does
not inject it automatically.

Alert on `/readyz` non-200, `queue_depth` sustained growth, `job_failures_total`
rate, and `dead` job count. A queue depth above 10,000 for ten minutes means the
worker is under-provisioned or failing.

## Backup and restore

Scripts live under [`scripts/`](../scripts/).

Backup:

```text
DATABASE_URL=postgres://... ./scripts/backup-postgres.sh
```

- `BACKUP_DIR` defaults to `backups`; `RETENTION_DAYS` defaults to 14.
- `pg_dump -Fc`; the new path is printed on stdout, diagnostics on stderr.
- Refuses an exported-but-empty `DATABASE_URL` or `POSTGRES_PASSWORD`.
- `POSTGRES_PASSWORD` is used as `PGPASSWORD` only when `PGPASSWORD` is unset.
- The dump is created with mode `0600`; a failed dump is removed.

Restore:

```text
DATABASE_URL=postgres://... ./scripts/restore-postgres.sh backups/aurifex-<stamp>.dump --confirm
```

- `--confirm` is mandatory.
- `pg_restore --clean --if-exists --no-owner`.
- Verifies `users`, `payments`, and `jobs` exist and prints their row counts as
  JSON. A missing table fails the restore report.
- Restoring a dump written before a schema migration requires running migrations
  afterwards.

Test restores into a separate database, never over the live one.

## Broadcast pacing

`/broadcast <text>` inserts a broadcast row and enqueues `broadcast.send` with
`idempotencyKey: "broadcast:" + broadcastId`. The worker pages `users` by
`id > last_user_id ORDER BY id LIMIT 100`, skips rows already in
`broadcast_deliveries`, and sends at most 30 messages per second globally. The rate
gate is a Redis fixed window `INCR broadcast:rate:<second>` with `EXPIRE 2`.
`retry_after` from Telegram is honored. Progress is committed per page:
`last_user_id`, `sent`, `failed`, and `status`. A crash resumes from the last page
without duplicating a delivery. `/broadcast_status <id>` is admin-only.

Telegram's 30/s limit applies per bot, not per worker. Running two workers is safe
because both use the same Redis window.

## Payment reconciliation

- `pre_checkout_query` validates payload, product, amount, and currency `XTR`, and
  answers within Telegram's 10-second window. It performs no write.
- `successful_payment` inserts with `ON CONFLICT (charge_id) DO NOTHING`, then
  enqueues `payment.fulfill` with key `payment:<charge_id>`. The reply is sent after
  the insert commits.
- Fulfillment grants once per `charge_id`.
- Refunds call `refundStarPayment`, insert a `refunds` row, and set the payment
  status to `refunded`. Repeated requests are idempotent.
- On grammY, boot enqueues the first `payment.reconcile` run 60 seconds after
  start. The job then reschedules itself into the next six-hour bucket. The aiogram
  runtime ships the job but not a boot-time enqueue; enqueue it once when enabling
  payments. The job pages `getStarTransactions` at limit 100, inserts missing
  incoming payments, marks refunds and chargebacks, and never grants an entitlement.

Review `payments`, `refunds`, and `subscriptions` after any incident that could have
interrupted delivery. Reconciliation records Telegram's state; it does not repair
a wrong entitlement already granted.

## Incident checklist

1. Declare the scope: bot token, webhook secret, database, Redis, LLM key, or user
   data.
2. Stop new work: `docker compose stop bot worker`. Keep Postgres and Redis up
   unless they are the compromised component.
3. Preserve logs and the current dump. Redact tokens, secrets, and user content
   before sharing.
4. If the token or webhook secret leaked: revoke and reissue the bot token, replace
   `secrets/bot_token` and `secrets/webhook_secret`, restart, and re-register the
   webhook with the new secret. The deploy plan reports the exact `setWebhook`
   parameters.
5. Check `/readyz`, then inspect `jobs` by status and the oldest `pending` row. A
   large `dead` set means handlers are failing; fix before replaying.
6. Check payment state before granting anything manually. Prefer reconciliation
   plus a refund over a duplicate entitlement.
7. Rotate database, Redis, and LLM credentials through `*_FILE`, then restart the
   bot and worker.
8. Restore only into an empty or deliberately replaced database, then run
   migrations.
9. Re-run `aurifex verify <root>` and the generated test suite. Confirm the token
   scan and webhook checks still pass.
10. Record the root cause and add a regression test; do not leave the incident
    response as an undocumented manual step.
